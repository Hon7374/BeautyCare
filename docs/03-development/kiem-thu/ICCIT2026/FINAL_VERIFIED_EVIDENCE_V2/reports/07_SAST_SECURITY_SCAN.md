## Before-remediation result

The preserved baseline JSON reports Semgrep 1.182.0, 40 discovery entries, 70 rules run, 5 findings, and 0 errors. All five findings are the same warning:

`javascript.express.security.injection.raw-html-format.raw-html-format`

They occur in `backend/routes/payments.js` at lines 1443–1449, in the mock payment HTML response. The rule reports WARNING severity, MEDIUM confidence, HIGH likelihood, MEDIUM impact, CWE-79, and an OWASP XSS/injection mapping. The affected values are interpolated into HTML generated by the `/api/payments/mock/pay` endpoint.

### Finding-by-finding assessment

| Finding | Location | Tool assessment | Manual risk assessment | False-positive assessment | Action |
|---:|---|---|---|---|---|
| 1 | `backend/routes/payments.js:1443-1444` | WARNING; raw user data in HTML | Reflected XSS risk if the `ref` query value is rendered without HTML escaping | Not dismissed; same underlying sink as findings 2–5 | Escaped with `escapeHtml` |
| 2 | `backend/routes/payments.js:1444-1445` | WARNING; raw user data in HTML | Same mock-page reflected-XSS sink | Not dismissed independently | Escaped with `escapeHtml` |
| 3 | `backend/routes/payments.js:1446-1447` | WARNING; raw user data in HTML | Provider/front-end display data must remain HTML-safe | The provider is constrained, but the output sink still warrants encoding | Escaped with `escapeHtml` |
| 4 | `backend/routes/payments.js:1447-1448` | WARNING; raw user data in HTML | Link/display interpolation requires context-appropriate encoding | URL construction is allowlisted/encoded, but the HTML sink is still reported | Escaped with `escapeHtml`; URL remains separately encoded |
| 5 | `backend/routes/payments.js:1448-1449` | WARNING; raw user data in HTML | Same reflected HTML risk in the mock response | Not treated as a confirmed exploit after remediation, but retained for tool review | Escaped with `escapeHtml` |

The five rows are not five independent vulnerabilities: they are five tool locations for the same mock-endpoint HTML construction pattern. Before remediation, the finding was treated as a real code defect because a safe fix was available.

## Remediation and after-remediation result

`backend/routes/payments.js` now applies context-appropriate HTML escaping to the displayed provider, reference, and front-end URL values. The allowlisted URL is still passed through `encodeURIComponent` for query construction. A regression test in `backend/tests/payment-mock-xss.no-db.test.js` verifies that a `<script>` payload is rendered as `&lt;script&gt;...`, is not returned as executable raw markup, and does not create a `javascript:` URL.

The post-remediation raw JSON and SARIF still contain 5 findings, with 0 fatal errors. Semgrep's OSS taint engine does not recognize the project-local `escapeHtml` function as a sanitizer in the original ruleset, so it reports the escaped interpolation sites. The preserved baseline also contains 4 post-remediation fixpoint-timeout records. A corrected scan excluding sensitive/non-source paths selected 37 JavaScript targets and, with `--timeout 0`, retained 3 fixpoint timeouts in `admin.js`, `auth.js`, and `payments.js`; therefore the corrected result has partial rule coverage. This is a tool-model/coverage limitation requiring manual review, not evidence that the remediation should be reverted. The honest status is **PARTIAL — scope verified, remediation applied, residual findings and timeout coverage require manual review**; it is not `PASS`, `BLOCKED`, or “0 vulnerabilities”.
